NIXOS CHEAT SHEET

=================

Quick reference for debugging, configuring, and working on NixOS.

YOUR SETUP

Config repo:

~/nixos-dotfiles

Flake host:

nixos-btw

User:

matt

Main config:

~/nixos-dotfiles/configuration.nix

Home Manager:

~/nixos-dotfiles/home.nix
CORE WORKFLOW

Check flake:

nix flake check ~/nixos-dotfiles

Build without changing the system:

sudo nixos-rebuild dry-build --flake ~/nixos-dotfiles

Build and switch:

sudo nixos-rebuild switch --flake ~/nixos-dotfiles

Test a configuration:

sudo nixos-rebuild test --flake ~/nixos-dotfiles

Build specific host:

sudo nixos-rebuild switch --flake ~/nixos-dotfiles#nixos-btw
IMPORTANT

Your Git repo is the source of truth.

Edit:

~/nixos-dotfiles/

Don't manually edit generated files in:

/nix/store/
~/.config/
GIT / CONFIG SAFETY

See what changed:

cd ~/nixos-dotfiles
git status
git diff

Recent commits:

git log --oneline --decorate -10

History for a file:

git log --oneline -- configuration.nix

See all history for a file:

git log --all -- configuration.nix

Restore a file:

git restore <file>

Compare with Git:

git diff -- <file>

Before deleting a backup:

git log --all -- <file>
NIX FLAKES

Show flake outputs:

nix flake show ~/nixos-dotfiles

Inspect metadata:

nix flake metadata ~/nixos-dotfiles

Check:

nix flake check ~/nixos-dotfiles

Update all inputs:

nix flake update ~/nixos-dotfiles

Update one input:

nix flake lock --update-input <input>

If something suddenly breaks after an update:

git diff flake.lock
git diff flake.nix
NIX STORE

Find where a program comes from:

which <program>
readlink -f $(which <program>)

Find matching store paths:

ls /nix/store | grep <name>

Search files inside an installed package:

grep -R "<thing>" /nix/store/*<package>* 2>/dev/null

Inspect package:

nix path-info nixpkgs#<package>

Run a package temporarily:

nix run nixpkgs#<package>

Enter a temporary shell with a package:

nix shell nixpkgs#<package>
IMPORTANT

Don't edit things in /nix/store.

They're generated by Nix.

PACKAGES

Search:

nix search nixpkgs <term>

Check whether a command exists:

which <command>

Find which package provides a command:

nix-locate bin/<command>
SYSTEM GENERATIONS

List generations:

sudo nix-env --list-generations --profile /nix/var/nix/profiles/system

See current generation:

readlink /nix/var/nix/profiles/system

Rollback:

sudo nixos-rebuild switch --rollback
Older generation

Reboot and select an older generation from the boot menu.

Garbage collection

Delete old generations:

sudo nix-collect-garbage -d

Delete generations older than 14 days:

sudo nix-collect-garbage --delete-older-than 14d

Be careful: garbage collection can remove old rollback generations.

SYSTEMD

Check service:

systemctl status <service>

Start:

sudo systemctl start <service>

Stop:

sudo systemctl stop <service>

Restart:

sudo systemctl restart <service>

Enable at boot:

sudo systemctl enable <service>

Disable:

sudo systemctl disable <service>

Failed services:

systemctl --failed

Running services:

systemctl list-units --type=service --state=running
User services
systemctl --user status <service>
systemctl --user restart <service>

Logs:

journalctl -u <service>

User service logs:

journalctl --user -u <service>

HYPRLAND CONFIG DEBUGGING

When Hyprland breaks:

1. Get the exact error.
2. Identify which layer produced it.
3. Read the error literally.
4. Form ONE hypothesis.
5. Change ONE thing.
6. Rebuild.
7. Check the error again.
8. Test the behavior.

Useful commands:

hyprctl configerrors
journalctl --user -b
hyprctl version

For Lua API questions:

grep -R "hl.<function>" /nix/store/*hyprland* 2>/dev/null

WHEN SOMETHING BREAKS
1. What changed?
git status
git diff
2. What exactly failed?

Get the exact error.

Then:

journalctl -b -p err
3. Which layer failed?

Think:

Nix
 ↓
Home Manager
 ↓
systemd
 ↓
application
 ↓
configuration parser
 ↓
runtime behavior
4. Can I reproduce it directly?

Try running the underlying command yourself.

5. What does my installed version say?
<program> --version
<program> --help
man <program>

Inspect /nix/store when appropriate.

6. Can I isolate the change?

Change ONE thing.

7. Did it actually work?

Don't stop at:

Build succeeded

Verify the actual runtime behavior.

THE MOST IMPORTANT DEBUGGING HABIT

Don't ask:

"What command fixes this?"

Ask:

"What observation would tell me WHY this is broken?"

That shift is what takes you from configuring Linux to actually debugging Linux.
